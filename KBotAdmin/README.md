# KBotAdmin

The owner's private administration program (slice ME01). **Not part of K-BOT's delivery: it must never be sent to a client or put in any K-BOT package, setup or update.** `publish-release.ps1` / `push-update.ps1` refuse any package that contains it. It is in `KBot.sln` for **Debug only** (so it shows in the start-up project list and F5 runs it; a Release build of the solution never builds it).

```powershell
dotnet build KBotAdmin\KBotAdmin.vbproj
dotnet run --project KBotAdmin\KBotAdmin.vbproj
.\publish-admin.ps1        # -> _Admin\KBotAdmin.exe (git-ignored; close the running program first)
```

`publish-admin.ps1` is the owner's own copy to run separately (needs the .NET 8 Desktop Runtime); it keeps the `admin_settings.json` of `_Admin` across publishes.

## Connection
- Only SSH (SSH.NET): key from `~/.ssh`, or a typed password / passphrase that is never saved. No database port is opened. Settings: `admin_settings.json` next to the exe (git-ignored; copy `Json\admin_settings.example.json`, which sits next to the exe in the `Json` folder): host, port, user, key path, `RemoteRoot`, `RemotePython`, pinned host-key fingerprint, `LocalRoot` (empty = the `PYTHON` folder next to `KBot.sln`), `PreserveMTime`, `ApiBaseUrl`, `IgnorePatterns`, `IncludeExtensions`.
- A dropped session (idle timeout, firewall) is reconnected on the next command; a keep-alive is sent every 30 s.
- Server half: `PYTHON/routes/admin_cli/` (push it with AvacontPush after every change there). The program runs `python -m routes.admin_cli.admin_cli <verb>` and reads one JSON object back; no free SQL is ever sent.

## Window

Account rights also synchronize the user's real MariaDB privileges (ME01-03). Before publishing this version, manually set up the separate privileged account using `sql/SEC03_kbotadmin_privilegii.sql` and server-side `DB_CONFIG_DREPTURI`. New personal MariaDB accounts can start with USAGE only (CREATE USER with a password, without initial ALL PRIVILEGES); assigning their application roles then grants the necessary data access. No schema changes or setup SQL are run automatically. Missing configuration refuses the rights change. Use **Aplică drepturile MariaDB** on existing accounts to remove their old broad grants without changing application roles. It applies to all assigned databases and all host variants of that username and closes the user's MariaDB connections. Accountants get data DML in their own databases, without server/schema administration. See `docs/worklog/SLICE-ME01-03-privilegii-mariadb.md` for policy and recovery details.

- The theme is switched from the theme button of the caption bar, like in K-BOT (`ThemeManager.Initialize`): it starts with the theme K-BOT has saved (Classic when none) and the choice is saved in the same theme settings, so both programs follow it. Uses `KBot.Controls` and `KBot.Theming` by project reference.
- Icon `KBotAdmin.ico` (K-BOT's blue rounded square with an X): exe, windows, caption bar, tray.
- The X button / Alt+F4 hides the window into the **tray** (no taskbar button). The tray icon menu (left or right click): «Afișează fereastra» and «Închide» (the only way to quit; it asks when an operation is running).
- A message box left open while the operator switches away and comes back is brought back in front (`ModalGuard`).
- At start only the databases and the accounts are read; every page reads its own data when it is opened.
- Errors: `<AppDir>\Logs\harness_errors.log`; messages shown to the operator: `Logs\mesaje_operator.log`; the file push traces every step in `Logs\publicare.log`.

## Pages (ribbon, ME01-05)
The window opens maximized. The ribbon has five tabs: **Baze de date** (Comenzi, Interogări unice, Sincronizare, Clonare DEMO), **Drepturi** (the page, the ADECHIT / VERCON rights windows, add account, access to a database, K-BOT role, Cereri, Resetare Login), **Monitorizare** (Loguri, Jurnal, Vizite, Server), **Copii de siguranță** (Copii server, Copii locale), **Publicare** (Publicare, Scripturi, Rapoarte VERCON). The left side is ONE tree with a tick on every row; the bar above it chooses «Baze de date» (the databases and, under each, its accounts; an account linked to several databases shows under each) or «Utilizatori» (the users and, under each, their databases); «Selectează tot» under it ticks every row (ME01-06; `AdminContext.CheckedDatabases` / `CheckedAccounts`, not used by any page yet). The «Diferență» page is no longer in the window (`DiffView*.vb` stay in the project, unused). `ButtonFit` widens button columns so a caption is never cut; `KBotSqlBox` (KBot.Controls) colours the SQL of the VERCON reports. Worklog: [ME01-05](../docs/worklog/SLICE-ME01-admin-desktop.md#slice-ME01-05).

Numai după confirmarea explicită a Adelinei, după testul ei, fișierele proprii, slice-ul și motivul se înregistrează prin `tools/Register-DeploymentTask.ps1`. Regula Codex este în `AGENTS.md`; instrucțiunile altor agenți nu sunt modificate. Nomenclatorul este `docs/deployment/pending/*.json`, fără tabele MariaDB. **Fișierele fără informații Git se pot trimite fără Git**. Cele cu informații valide păstrează salvarea versiunilor existente înainte de suprascriere. Dacă au fost editate după confirmare, trimiterea normală cere fie o nouă confirmare, fie modul debugging.

**Publicare debugging (fără Git)** trimite toate fișierele bifate fără Git, inclusiv dacă au informații Git, care rămân păstrate. Serverul reține căile și amprentele publicate în evidența privată `.kbotadmin-deployment/debug.json`. La scanare apar și fișierele debugging cu timpi identici sau fără sursă locală.

**ME01-18:** fișierele deja publicate debugging sunt comparate prin SHA-256 cu conținutul actual de pe server, indiferent de timpi. Cele neschimbate apar «DEBUGGING», nebifate în coloana «Trimite»; lipsa informațiilor Git nu le selectează pentru o nouă trimitere. Cele cu conținut diferit apar «MODIFICAT», bifate la «Trimite», iar cele lipsă de pe server apar «NOU», bifate la «Trimite». Numărul pe extensie al fișierelor de trimis nu include rândurile «DEBUGGING». Bifarea manuală la «Trimite» și «Bifează tot» permit în continuare retrimiterea explicită.

**ME01-19:** «Finalizează debugging» folosește exclusiv bifele din coloana «Debugging», independent de «Trimite». La scanare, fișierele din evidența debugging sunt bifate în coloana «Debugging»; operatorul poate debifa individual versiunile pe care nu dorește să le finalizeze. Pentru fișierele fără evidență debugging, această bifă este inactivă. «Bifează tot» și «Debifează tot» schimbă numai coloana «Trimite». «Trimite bifatele» citește numai coloana «Trimite».

După test și confirmarea explicită a Adelinei, agentul înregistrează slice-urile și motivele pentru fiecare fișier. Selectați versiunile testate în coloana «Debugging» și apăsați **Finalizează debugging**: butonul folosește direct informațiile deja existente, fără dialog de completare sau confirmare suplimentară, și face numai Git pe server pentru versiunile selectate. Dacă informațiile nu corespund amprentelor debugging sau fișierele de pe server s-au schimbat, finalizarea este oprită. Fișierele aplicației nu se reîncarcă, nu primesc spații sau alte schimbări artificiale, iar serviciul nu se repornește. Informațiile locale incluse și intrările debugging finalizate se șterg numai după succes; restul se păstrează.

**După închiderea și redeschiderea KBOTADMIN**, fișierele de finalizat apar din nou la scanarea aceluiași server și aceleiași rădăcini: evidența este în `RemoteRoot/.kbotadmin-deployment/debug.json`, iar informațiile Git sunt pe disc, în `docs/deployment/pending`. Închiderea aplicației nu șterge niciuna dintre evidențe.

Fișierele ajung întâi într-o zonă temporară privată. Git rulează **pe server**, salvează numai versiunile existente ale fișierelor selectate **înainte de suprascriere**, apoi se încarcă versiunile pregătite. Prima linie a commitului conține slice-urile, separate cu `; `; subslice-urile aceleiași familii folosesc minim/maxim (`SLICE-AB12-02/09`), chiar dacă nu sunt consecutive. Motivele sunt rânduri cu `- ` separate prin CRLF. Înregistrările lotului se șterg numai după confirmarea succesului încărcării și commitului; cele noi sau nepublicate rămân.

Transferul fișierelor rămâne prin SFTP, iar comenzile serverului prin SSH. Depozitul și identitatea Git sunt necesare numai când se cere Git, nu pentru debugging. Nu se inițializează automat depozitul și nu se execută Git local. Lansarea `Push-Changed` din Scripturi rămâne blocată deoarece nu păstrează evidența debugging. **Tabele** (ribbon: Baze de date > Răsfoire; ME01-08, 02.11.2026): the tables of the database chosen in the left tree, opened read-only. In `SplitContainer`s resized with the mouse: the tree of tables (and views) on the left, grouped by the prefix of the name (`AD_`, `VC_`, `FX_`...; the rest in `_Fara Grupare`, first), without a root for the database; the rows grid (`KBotDataView`, first 1.000 rows, «Încarcă încă 1.000» for more) top right; under it a read-only `KBotRichTextEditor` with the whole cell (half of the width, ~20% of the height) and two key/value grids, one for the table and one for the chosen column (type, PK, FK and the column it points at, what refers to it). Widths come from the type: ids 100 px, dates and date-times as wide as their format, numbers with thousands separator (decimals only for non-integers), `tinyint(1)`/`bit(1)` as tick boxes, long texts a preset width with ellipsis, blobs as «<BLOB>» (double click: modal window with a hex dump and «Salvează ca fișier...»; a cut long text opens whole there too). The preset widths are maxima of the first display: a column is as wide as its header and first rows need, never wider, and the mouse widens it freely. Header menu by type: text and dates sort, filter and group (a date groups by day, month or year, never by time), long texts and numbers sort and filter, tick boxes only sort. Header and cell tooltips show what does not fit. Nothing is editable. Server half: `routes/admin_cli/admin_dbview.py` (verbs `db-tables`, `db-table`, `db-rows`, `db-cell`; push by hand). Never run. Worklog: [SLICE-ME01-08-tabele-baze](../docs/worklog/SLICE-ME01-08-tabele-baze.md). **Linked tables:** the cells of a column that is a foreign key (or is pointed at by other tables) are drawn like links (underlined, the hand cursor over them; NULL cells stay plain): a foreign key in the accent colour of the theme, a column only pointed at by other tables in its success colour and ONE click on such a cell opens a popup with the linked tables (a double click keeps only the content window of blobs and long texts); the one chosen opens with only the rows equal to the cell (filtered by the server, `--where-json`; a composite key asks the other columns in a combo you type in, limited to the list, the values that contain the typed text coming from the server after the first character, verb `db-distinct`). Under the grid, ◀ / ▶ walk the history of those steps (a popup lists the steps when there are several); a table opened from the tree starts a new history. What was read stays in memory until «Reîncarcă» (flat, transparent button). The walk can be logged in `Logs\tabele_navigare.log`: OFF at every start, switched on with the tick box «Jurnal navigare» in the ribbon group at the right (only on the page «Tabele»). **Copii locale** (ME02): encrypted copies of the unit databases on THIS PC, kept in the folder chosen with «Dosar...» (`BackupRoot` in
`admin_settings.json`). Format and cryptography: `docs/ME02_FORMAT.md`; the server half is `routes/admin_cli/admin_snapshot.py` (read only). The page offers «Copie acum» (asks for a reason), «Verifică», «Export SQL» (a file for a scratch database `zz_...`), «Istoric rând», «Curăță» (retention; manual copies are never removed by it) and «Șterge» (the only way a manual copy disappears). **Tabele > «_Interogari»** (ME01-12, 02.11.2026): the first group of the tree on the page «Tabele». Each row is a query of the local catalog (`KBotAdmin\Interogari\*.sql`, plain files read from disk every time, NOT in the exe; the folder is found next to `KBot.sln`, or set `QueriesFolder` in `admin_settings.json`; header of `-- @title` / `-- @description` / `-- @param name | label | type | explanation` lines, then read-only SQL with `:name` parameters). A left click or Enter opens a modal window with what the query does and one field per parameter (up to 6) with its explanation; «Rulează» checks the types (text, int, number, date) and runs it on the chosen database through the verb `query-run` (`PYTHON/routes/admin_cli/admin_query.py`: one SELECT / WITH / SHOW / DESCRIBE / EXPLAIN, READ ONLY transaction, 60 s, at most 5.000 rows). The rows show in the same grid as a table (no paging, no links, no history; «Reîncarcă» runs it again). Nothing is created in the databases or kept on the server. To add or change a query: only the `.sql` file; «Reîncarcă» (or just a click on its row) shows it: no build, no `publish-admin.ps1`, nothing on the server (the verb `query-run` must be there once). A file with a broken header is a row «(greșit)» that says what is wrong. Never run. Worklog: [SLICE-ME01-12-tabele-interogari](../docs/worklog/SLICE-ME01-12-tabele-interogari.md).
