# Project instructions

- Orice lucrare se face pe un slice de forma `SLICE-wwnn-nn`, unde fiecare `w` este o literă sau o cifră, iar fiecare `n` este o cifră.
- **REGULA 0 — Limita intervenției:** Dacă o modificare ar afecta mai mult decât scopul discutat și autorizat cu utilizatorul, asistentul se oprește și îl anunță înainte de a continua. Nu extinde automat modificarea la alte tabele, module, documente sau fluxuri.
- **IMPORTANT — Planurile Codex:** Salvează toate planurile exclusiv în `docs/plans/`, în repository.
- The assistant has no authorization or access to modify MariaDB schemas. Prepare DDL and seed SQL as files for the user to execute; never execute schema changes or add automatic schema creation to application code. Applies to AVACONT_COMUN and all other MariaDB databases.
- SQL supplied for AVACONT_COMUN must use uppercase identifiers for new tables and columns.
- Do not run tests or other verification unless the user explicitly requests it. Design checks are allowed.
- **IMPORTANT — Închiderea taskurilor Codex (SLICE-ME01-07):** La finalul fiecărui task, după CONFIRMAREA EXPLICITĂ A ADELINEI, înregistrează toate fișierele proprii create/modificate, inclusiv documentația și resursele. Numai după această confirmare, agentul execută `tools/Register-DeploymentTask.ps1 -Slice SLICE-wwww-nn -Reason 'motiv concret' -Files @('cale/relativa/fișier', ...)` pentru TOATE fișierele create/modificate în acel task (cod, resurse și documentație; fără fișierele registrului însuși). Nu se enumeră fișierele altor taskuri și nu se inventează motive pentru modificări străine. Dacă ulterior mai editează un fișier, îl înregistrează din nou numai după confirmarea explicită a Adelinei pentru modificările ulterioare. Fără confirmare, nu se execută înregistrarea. Registrul este `docs/deployment/pending/*.json`; înregistrările sunt imuabile, cu SHA-256, și nu se șterg manual. KBOTADMIN elimină numai înregistrările lotului publicat după confirmarea salvării Git pe SERVER și a încărcării reușite. Dacă înregistrarea eșuează, taskul se raportează neînchis. Procedura: `docs/deployment/README.md`. Nu se execută Git local pentru acest mecanism. Regula se păstrează numai în instrucțiunile Codex; nu se modifică `CLAUDE.md` sau instrucțiunile altor agenți.
- **IMPORTANT — Probe și publicare debugging (SLICE-ME01-09/10):** fișierele pot fi publicate pentru probe fără Git. Lipsa informațiilor Git nu blochează transferul; bifa «Publicare debugging» omite Git pentru întregul lot, inclusiv dacă există informații Git, care se păstrează. Evidența automată pe server a fișierelor debugging și a amprentelor lor nu reprezintă aprobarea pentru Git. Înregistrarea informațiilor Git se face numai după CONFIRMAREA EXPLICITĂ A ADELINEI, după testul ei; nu se consideră confirmare simpla cerere de implementare sau publicare debugging. Agentul înregistrează slice-urile și motivele pentru fiecare fișier ÎNAINTE ca Adelina să ceară finalizarea. «Finalizează debugging» folosește direct aceste informații existente și face numai Git pe server pentru versiunile debugging selectate, fără dialog de completare, fără o confirmare suplimentară, fără generare de metadate noi, fără reîncărcarea fișierelor și fără repornire. Evidența debugging se păstrează pe server și se recitește la scanare după redeschiderea KBOTADMIN; nomenclatorul Git se păstrează pe disc în proiect. Nu se adaugă spații, comentarii sau alte modificări artificiale în cod pentru a forța detectarea. Instrucțiunile celorlalți agenți, inclusiv `CLAUDE.md`, nu se modifică.
- În toate aplicațiile, datele afișate se ordonează după tipul real: texte alfabetic în limba română, date calendaristice cronologic, numere numeric (inclusiv zecimale și valori negative), niciodată după ID-ul intern sau șirul de afișare. Regula se aplică arborilor la fiecare nivel, listelor, selectoarelor, grilelor și filtrelor, inclusiv după încărcare lazy, căutare și reîmprospătare. Etichetele compuse folosesc chei de sortare explicite. Sensul crescător/descrescător ales în ecran se păstrează. În machetele documentelor, rândurile de total, antetele și structura impusă explicit se păstrează în poziția lor.

- **DGV + tree bands (KBotDataView and AdvancedTreeControl) — every grid and tree in App and EFactura (operator, 07.11.2026).** The header and footer are 30 logical pixels (`HeaderHeight` defaults to 30 and `FooterHeight` follows it), with Calibri 9 pt Bold. Band colours follow the theme defaults in `KBotDataView.Theming.vb`. Classic uses `Control` for the background and `Gainsboro` for the separator. Modern and other themes use their derived defaults.
  - On a new or edited grid or tree, omit `HeaderHeight`, `FooterHeight`, `HeaderFont`, `FooterFont`, `HeaderBackColor`, `FooterBackColor`, `HeaderSeparatorColor` and `FooterSeparatorColor` from the designer and code. Omit column `HeaderFont` as well. For a tree, also omit `FooterCaptionFont`, `FooterCaptionBackColor`, `HeaderSeparatorWidth` and `FooterSeparatorWidth`. The footer caption has a transparent background. Remove these assignments if the designer generates them. Make appearance changes in the shared control.
  - A tree caption that labels an icon shares the icon's hover plate and raises its click event (`FooterRightIconClicked`, `FooterLeftIconClicked` or `HeaderRightIconClicked`). In the footer, the caption belongs to the right icon. Use the left icon if it is the only icon, or if both icons exist and the caption is left-aligned. In the header, a right-aligned caption labels the right icon. Left- and centre-aligned captions are plain titles. Use the existing icon events for caption clicks.
