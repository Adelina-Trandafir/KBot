## How it was made, and its limits

Generated by `tools/AccessMap/extract.js` (reads the whole export into a graph) and
`tools/AccessMap/build-efactura.js` (writes these files); the overview is hand-written.

```powershell
node tools\AccessMap\extract.js Surse\RawExport <scratch>\graph.json
node tools\AccessMap\build-efactura.js <scratch>\graph.json Surse\RawExport docs\access-map\efactura
```

- References are found by reading text: SQL in `RecordSource` / `RowSource` / queries / quoted strings in VBA,
  `DoCmd.Open*`, `Forms!X`, names of public procedures. SQL assembled from variables, `Eval`, and objects opened by
  a name held in a variable are **not seen**. Treat "Reads / Writes" as a lead, then read the code.
- "Writes" = `INSERT INTO / UPDATE / DELETE / SELECT INTO` text, plus tables opened with `OpenRecordset` in a procedure that
  calls `AddNew` / `Edit`.
- Scope = forms named `EFACTURA_*`, `EF_*`, and the association forms; modules `mdl_EFactura*`; classes `clsEF_element`,
  `clsAnaf_Async`; every table and query those touch (transitively through queries). Tables outside the `EF`
  family are listed as "shared".
- Control positions are Access twips (1 inch = 1440 twips = 96 px at 100 %). `LayoutCached*` values are preferred
  because Access keeps them in sync with what is on screen.
- Passwords in link strings are masked in the export and stay masked here.

## Form-page conventions

These conventions apply to the 21 form records (19 pages after grouping the three PDF viewers); every record retains its source filename, source character count and raw-export path.

Units are twips (1 inch = 1440). `Parent` is the tab page or group a control sits in, or - for a label - the control it is attached to. Positions are relative to the section that holds the control; `LayoutCached*` values are used when present.

The exact RecordSource SQL is kept once in the page's Data section; its properties row links there when it previously repeated the same SQL. Different SQL, bindings, controls and event rows are not deduplicated across forms.

### Module declarations

Form state is the variables, constants, types and WithEvents helpers in the Access class body before the first procedure. In the 20 form-class records that reference this section, the following exact attribute prefix occurs before any additional declarations:

```vb
Attribute VB_GlobalNameSpace = False
Attribute VB_Creatable = True
Attribute VB_PredeclaredId = True
Attribute VB_Exposed = False
```

A page saying "only the common attribute prefix" had no additional declarations in its export. Mesaj_ANAF did not have a module-declarations section; this convention does not invent one. Additional attributes, WithEvents fields, events and even source comments remain on their own form page.
