## Subunits = the units of the DC (operator, 25.10.2026, third pass) - supersedes "default subunit" below
The first subunits dialog (one add form, everything into the default subunit) was wrong. Now **one Access unit (a `cai` row) = one subunit**:

Only STORED for now: the windows that read classifications / budget will use it in a later slice. The dialog refuses a parent that is not in the DC or not ticked / ported.
- **PlanCont step**: no more «one unit only» blocker. Each unit's accounts go into the subunit found by `IdUnitateAccess`; a unit without one = blocking finding (kind `SUBUNITATE_LIPSA`, offers to open the dialog). One summary line per unit.

## What changed and why
The operator ran `AV01_04b_plancont_sursasector.sql` and asked to go on. The Access chart of accounts (`PlanCont`, 351 rows in `baza2026.accdb`: one row = one full account with its SID / SIC / RPD / RPC) now has a way into the new tables, inside the existing Migrator (same verify-then-transfer flow, same journal).
- **New table family in the catalogue**: `TableMaps.Nomenclators()` has `PlanCont -> TZ_PlanCont` flagged `AsPlanCont("TZ_SoldInitial")` (like `AsPartnerLinks`): it is NOT written by the column-by-column writer, because one Access row feeds two tables and the symbol has to be split.
- **Reader** (`Transfer/PlanContSet.vb`): per ticked unit it reads `SimbolCont, Cont, Analitic, DenumireCont, FelCont, CodSector, Sursa, ClsfF, ClsfE, Extra, SID, SIC, RPD, RPC`. Base account = the first 7 digits of `Cont`; sector+source = `CodSector` + `Sursa`; amounts to 2 decimals; `Extra` Yes/No or Da/Nu. The symbol written is the COMPOSED one (cont + sector/source + ClsfF + ClsfE + .analitic), the one the window and the server compose.
- **Verifier** (`Verifier.CheckPlanCont`, called in the partners step): BLOCKS when the target has no default subunit (the chapter is in no Access table: create the first subunit in the window before migrating), when more than one ticked unit has PlanCont rows (they would be mixed in one subunit), when a base account / sector+source / ClsfF / ClsfE is not in `AVACONT_COMUN`, when ClsfE has no ClsfF, when a value is too wide or an amount is negative, or when two rows compose the same symbol. WARNS about a classification the base account does not allow, a Fel not A/B/P, an analytic outside the rule, a composed symbol that differs from the Access key (lists them), and about accounts that already exist in the subunit. INFO: blank Fel / name filled from the base account; one summary line (accounts, balance rows). Also checks the columns of both tables (1364 guard) and that `TZ_Subunitati`, `TZ_SoldInitial` exist.
- **Writer** (`TransferRunner.WritePlanCont`): into the default subunit, `INSERT ... ON DUPLICATE KEY UPDATE IdCont = LAST_INSERT_ID(IdCont)` (an existing symbol is left as the operator edited it), then `TZ_SoldInitial` (year `TableMaps.TransferYear` = 2026, partner NULL, only for accounts with a non-zero balance or turnover; debit before credit). Journal lines and progress as the other tables; any failure rolls the whole transfer back.
- `ParteneriSI` (balances per partner, 52 rows) stays in the exclusion list: no window or target usage yet.
