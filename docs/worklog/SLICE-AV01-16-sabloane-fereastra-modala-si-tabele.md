# SLICE-AV01-16 - «Sabloane»: modal window, one table per operation, salary views (operator, 29.10.2026)

## What changed and why
The operator asked for a rework of the «Sabloane» window (16 points). Done on the three pages (`SablonOperatiiView` for types M and A, `SablonSalariiView`):

0. **Source of the title bar.** The window is now modal, so it shows the sector+source (and the year) the title bar had when it opened, in its own title («K-BOT — Sabloane · operatii cu clasificatie · 02E · 2026», «toate sursele» on «Toate»). The three pages
   already filtered on it; the salary page now filters the CHAPTERS of the tree on it. To work on another source the window is closed, the source changed and the window opened again (the title bar cannot be touched under a modal window).
1. **Modal popup.** `SabloaneForm` inherits `KBotModalForm`; `KbotForm.DeschideSabloane` opens it with `ShowModalAsync` like «Jurnale» (not a page, not in the history: the `sabloane` macheta type was dropped from `KbotForm.Machete.vb`, the ribbon calls `DeschideSabloane` directly).
2. **Size** 1900 x 1000 at 150 % = 1267 x 667 at the 96-dpi designer (`ClientSize`). `AvacontMain.FitModal` still cuts it down to the work area on a small screen.
3. **Trees 40 %** of the width on all three pages (`tlyBody` 40 / 60).
4. **Header fields 30 % higher** (32 -> 42): Explicatie, Cod jurnal, Tip operatie, Fel factura. «Compartiment» was NOT in the operator's list and stays at 32.
5. **ONE table for the lines** (`gridLinii`, a `KBotDataView`), replacing the pager. Type M: one row per FORM of the classification; columns Clasificatia (read-only, composed from the key and the form), Cont debit / Cont credit (editable combos, «symbol - name»),
   Part. debit / Part. credit as ticks (ticked = the partner of the operation, `OPERATIE` mode, replaced when the operation is made; ticking one side clears the other; fixed partners are no longer chosen here, a line that already has one keeps it until
   a tick is touched), and the flags O / P/A / C. «Adauga linie» / «Sterge linia» are gone. Type A keeps the partner combos and has free rows («+» in the grid footer, «✕» per row).
6. **Tree option** (type M): the right button of the tree header opens a popup with «Arata doar clasificatiile cu operatii», default off.
7. **Bold nodes**: every node above an operation is bold (titles, articles, paragraphs, «Alte clasificatii»).
8. **«+» on hover** on the last level before the operations (paragraph, or the article when the paragraph is «00») in type M; type A keeps the first row «Adauga operatie diversa». One node can stand for several chapters (a «00» paragraph): then «+» asks which classification.
9. **Hover button on every operation / article**: a popup with «Modifica» / «Sterge». «Sterge» asks, then stages the delete (written at «Salveaza»).
10. **Footer**: only «Salveaza» (20 % taller: row 52 -> 62, button padding 3 -> 6), enabled when «Modifica» or an «Adauga» unlocked the page, or when something is pending. The right-hand side is locked (`Enabled = False`) until then.
11. **Salarii**: «Capitol» and «Clasificatia articolului» are gone from the right side; the tree is 40 % like the rest. The chapters are now the first level of the tree (bold when they have articles, «+» on hover adds an article); the classification of the article is
    the FIRST COLUMN of the «Angajamente» table (it had to stay somewhere editable).
12. **Salarii**: the first table (Angajamente) has its header and row 30 % taller (24 -> 31). With point 14 it can no longer be «taller» by frame, so it is taller by row.
13. **Salarii**: Retineri / Viramente / Numerar end with an empty row; typing in it makes it a line (new negative ref, «✕», treasury 7700000 on a virament, the article's credit on a retention) and a new empty row follows. The «✕» button is a plain filled rectangle
    (`ButtonBorders = None`, `ButtonMargin = 0`) so it is the cell. The footer «+» of these tables is gone.
14. **Salarii**: a horizontal bar «Angajamente / Rețineri / Viramente / Numerar» (`KBotNavList`) over four tables, one at a time, each taking the whole height. The bar stays alive while the tables are locked.
15. **Salarii**: hover buttons on the nodes like in the other trees (see 8, 9).
16. **Salarii**: «Salveaza» is the only button («Sterge articolul» is now the hover menu).

## Unverified / deferred
- **Nothing was seen on screen**: the layout at 1267 x 667, the 42-px rows, the 40 / 60 split, the horizontal bar, the tick columns, the hover buttons (`ShowRightIconOnHover` per node) and the popups were never drawn.
- **P and A**: the operator named four flags (O, P, A, C); the data has THREE (Ordonantare, `PA` = «Propunere / Angajament», Chelt). The table has O, **P/A**, C. A real split of P and A needs a column in `TZ_SablonOperatiiLinie` and a server change - not done.
- «Cont debit / Cont credit linked to the classification of the row»: understood as «the account of THAT line» (each row is one form); the account lists are not filtered by classification.
- On «Toate» a new operation gets the first journal of the list (as before); the journal combo shows «SS cod» so the source can be chosen there.
- Typed accounts in the type-M table must be on the list (number or «number - name»); an unknown one is refused with a message in the status line.
- A cell edit still open when the window is closed is not counted as pending (the click on the close button normally commits it first).
