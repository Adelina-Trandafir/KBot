# SLICE-ME01-08 - KBotAdmin «Tabele» (02.11.2026)

Owner's tool only (KBotAdmin, never published). A read-only browser for the tables of one unit database, in the ribbon tab «Baze de date» > «Răsfoire» > «Tabele» (key `tabele`).

## What it does
The database is the one chosen in the left tree of KBotAdmin (`<TOATE BAZELE>` is refused with a hint on the page). Only the unit databases are reachable (the same rule as every other verb: never AVACONT_SURSA / AVACONT_COMUN).

Layout: `SplitContainer`s all the way (the house `KBotTableLayoutPanel` has no mouse resizing), so every border is dragged by the operator. Starting proportions are set once, in `DbBrowserView.ApplyRatios`: tree ~270 px; under the rows ~20% of the height; in that strip the cell box takes 50% of the width and the two fact grids 25% each.
- **Left, tree** (`AdvancedTreeControl`): no root for the database (the main tree already says which). Roots are groups by the first 3 characters of the name when they look like `AD_` / `VC_` / `FX_` (two letters or digits + underscore, with the count), shown under the owner's names: AD_ = ADECHIT, EF_ = EFACTURA, FX_ = FOREXE, TZ_ = AVACONT, VC_ = VERCON (`DbBrowserView.GroupNames`; any other prefix shows as it is), ordered by the name shown (ADECHIT, AVACONT, EFACTURA, FOREXE, VERCON), not by the prefix; the tables under a group show without the prefix (Prezenta, not AD_Prezenta), the tooltip and the server calls keep the full name; everything else goes in the group `_Fara Grupare`, always first, the others alphabetical. Tables and views live in the same groups (a view says «vizualizare» on the right, a table its estimated rows). Only the group of the open table is expanded after a reload. A click on a table opens it.
- **Right top, rows** (`KBotDataView`, read-only, nothing editable): the first 1.000 rows; «Încarcă încă 1.000» appends the next page; «Reîncarcă» re-reads the list and the open table. Sorting and filtering work on the loaded rows only.
- **Right bottom**: `KBotRichTextEditor` (read-only, no header/footer) with the whole content of the chosen cell; grid «Tabel» (key/value, 25%); grid «Coloană» (key/value, 25%). A click on a fact row shows its value in the cell box (long lists such as indexes or foreign keys).

Column rules (decided from the MariaDB type; `DbBrowserView.BuildColumns`):
1. Integer ids (primary key, foreign key, or a name starting with `Id` / ending with `Id` / `_id`): 100 px, plain digits.
2. `date`: as wide as «88.88.8888» measured with the grid font; shown `dd.MM.yyyy`.
3. `datetime` / `timestamp`: as wide as «88.88.8888 88:88:88» (+ the fraction digits of the column); shown `dd.MM.yyyy HH:mm:ss`.
4. Numbers: thousands separator; decimals only for `decimal` (the column's scale) and float/double; whole numbers have none. Right aligned.
5. `tinyint(1)` and `bit(1)`: a tick box. Other `tinyint` stay numbers.
6. A header cut by the width gets a tooltip with the full name and the type.
- **Widths (02.11.2026):** the preset above is the MAXIMUM of the first display. When a table opens, each column is as wide as its header and the text of its first 300 rows need, never wider than the preset (`FitColumns`). The column has no `MaxWidth`: the mouse widens it as much as wanted, and nothing refits later. Date and date-time columns get 40 px of room (the cell padding cut the text measured to the pixel).
- **Header menu by type (02.11.2026):** char / varchar / enum / set and dates: sort + filter + group; text / longtext, numbers, time: sort + filter; tick boxes: sort only; blob: no menu. A date or date-time groups on the day (the time never counts), the month (`MM.yyyy`) or the year; chosen in the Grupare tab (new row «Pe zi / Pe lună / Pe an»). New in KBot.Controls: `KBotGroupDatePart` + `KBotGroupLevel.DatePart` (key = date part of the raw value, groups ordered by the date), `KBotDataColumn.AllowFiltering` (False hides the Filtrare tab, so a sort-only menu is possible).
7. The grid's own cell tooltip shows a cell that does not fit (texts end with an ellipsis).
- `text` / `mediumtext` / `longtext`: 260 px, line breaks shown as spaces; `varchar` / `char`: by the declared length (70..320 px); `enum` / `set`: 120 px.
- Blob types (`blob`, `varbinary`, `binary`, ...): the text «<BLOB>». Double click opens a modal window (`CellContentForm`): hex dump of the first 64 KB + «Salvează ca fișier...» (all bytes the server sent, max 8 MB) + «Copiază». A long text that the server cut (over 32.000 characters in a page) is fetched whole on double click and shown in the same window; a long text that came whole opens there too.
- NULL: an empty cell (the cell box says «(NULL)»).

«Coloană» grid: name, position, type, length / precision, NULL, default, extra, collation, primary key (and its position in a composite key), foreign key + **the table.column it points at** + ON UPDATE / ON DELETE + the constraint, the tables that point at the column, indexes, comment. «Tabel» grid: type, engine, collation, estimated and loaded rows, data/index size, auto-increment, created/updated, columns, primary key, foreign keys, referenced by, indexes, comment.

## Server half
`PYTHON/routes/admin_cli/admin_dbview.py` (new; registered in `admin_cli.py`): verbs `db-tables`, `db-table` (info + columns + keys + first page), `db-rows`, `db-cell`. They only SELECT. The table and the column are checked against `information_schema` before reaching SQL and quoted; the key of a row for `db-cell` must be exactly the primary key. A page never carries blobs (only their length) nor more than 32.000 characters of a text. Rows are ordered by the primary key (stable paging); a table without a primary key is paged unordered and a cell is found by position (the window says so). **Push this file by hand with AvacontPush** (never deployed from here).

## Linked tables, history, cache (02.11.2026)
Asked by the operator: (1) double click on a cell that leads to other tables shows a custom popup (`CustomPopup`) with them; (2) choosing one opens it filtered to the value of the cell; (3) ◀ / ▶ under the grid; (4) what was read is kept, and only «Reîncarcă» reads again.

- **One click, links drawn as links (02.11.2026, operator):** the double click was dropped for the jump: ONE click (`GridData_CellClick`) on a cell of a link column opens the popup. A column is a link column (`_linkColumns`, computed in `BuildColumns`) when `LinksOf(column)` is not empty and its kind is not a tick box, blob or long text. Its non-NULL cells are drawn by `GridData_CellFormatting` with an underlined twin of the cell font (`_linkFonts`, made once per font, disposed with the view) and TWO colours of the theme palette (nothing written in code): **a foreign key of the open table (leads OUT, `→` in the popup) = `Palette.AccentColor`** (blue in Classic, which KBotAdmin keeps fixed); **a column only pointed at by other tables (leads IN, `←`) = `Palette.SuccessColor`** (green in Classic). `_linkColumns` holds, per column, whether it is a foreign key; a column that is both counts as a foreign key (its popup still lists both kinds). **The hand cursor** over a non-NULL link cell: new event `KBotDataView.CellCursor` (`KBotCellCursorEventArgs`, in `KBot.Controls/DataView`, raised from `OnMouseMove` over data cells with the cursor the grid would set; additive, no other grid changes) answered by `GridData_CellCursor`. The double click stays only for the content window of blobs, cut texts and long texts.
- **Which cells lead somewhere:** the column is a foreign key of the open table (-> the referenced table, marked `→`), and/or other tables' foreign keys point at it (`←`, from `ReferencedBy`). Only tables of the open database (the server reads no other); NULL leads nowhere; blobs, cut texts and long texts keep their content window. The popup's first (greyed) row says which column / value it is. A composite key (a foreign key of several columns) asks for the other columns, see below.
- **Filter is made by the server** (`db-table` and `db-rows` take `--where-json J`, a JSON object {column: value}, every column must equal its value; `admin_dbview._where` checks every column against the real columns and passes the values as parameters), so it covers the whole table, not only the loaded 1.000 rows. «Încarcă încă» keeps the filter. The row tag keeps the JSON of every cell (`RowTag.Cells`), so the value goes back to the server exactly as it came (dates, decimals).
- **Composite keys (follow-up, 02.11.2026):** when the chosen link pairs several columns (`LinkTarget.Columns` / `SourceColumns`), the value of the clicked column is known and every OTHER column is asked, one by one, in a small window `LinkValueForm` (KBotAdmin\LinkValueForm.vb + .Designer.vb) with a `KBotComboBox`: `Editable = True` (the operator TYPES), `LimitToList = True` (a text that is not one of the values does not stay in the field and «Alege» refuses it: the answer is never empty or invented), `FindAsYouType`, `FindAfterNChars = 1`. The values are NOT all brought: after the first character typed the page asks the server (`db-distinct --db --table --column --where-json --like=TEXT --limit 200`) for the values that CONTAIN the text, those that START with it first (`CAST(col AS CHAR) LIKE`, `%` / `_` / `\` escaped, case and accents as the column collation; NULL out; `GROUP BY`), only from the rows that match what is already chosen. Typing more narrows the list already there (the combo's find-as-you-type); the server is asked again only when that list was cut at 200 or the text no longer extends what was asked. A row picked from the list closes the window; «Alege» takes a typed text only if it is a value of the list (`CommitText`). Closing the window (Esc / «Renunță») cancels the whole jump. The answers are cached in `_distinctCache` (key includes the typed text), cleared by «Reîncarcă». The view keeps every condition (`NavNode.Filters`); the label and the «Filtru» row of the table facts show all of them. (The first version of this follow-up used a popup combo with ALL the values and no typing: replaced at the operator's request.)
- **History = a TREE** (`NavNode`: table + filter, parent, children). A table opened from the left tree starts a new history (no «back»). ◀ is active when the view has a parent; with one step behind it goes there, with several a popup lists them (nearest first) and a pick jumps there. ▶ is active when the view has children (`ForwardList`): while a view has ONE child that child and then its children are listed in order; where a view has several, those are listed and the walk stops. So T1>T2>T3, back, back, T1>T4>T5, back to T1: ▶ offers only T2 and T4. A step taken again (same table + column + value) reuses its node, so what lies behind it is still there. A node joins the tree only after its rows were shown; the left tree follows (selects the table of the view).
- **Cache** is in MEMORY, per run of KBotAdmin (not on disk): `_tablesCache` (list of tables by database) and `_viewCache` (database + table + filter -> `DbTableResult`, which also grows with every «Încarcă încă» page). «Reîncarcă» clears both for the chosen database and reads the list and the open view again (the history stays).
- **«Reîncarcă»** is now a plain flat `Button` (no inner padding, square corners); `DbBrowserView` is an `IThemedContainer` whose `ApplyTheme` puts `ButtonStyles.ApplyTrans` back over the generic button look (ThemeManager themes the children first). ◀ ▶ are the same kind of button, text `◀` `▶`, in a new row of `tlyTop` (`tlyFoot`).
- **Log of the walk (02.11.2026, asked by the operator to check the navigation; ON ONLY BY CHOICE):** it is OFF at every start of KBotAdmin and `TableNavLog.Write` does nothing (no file touched) until the operator ticks the tick box **«Jurnal navigare»**, in the ribbon's RIGHT group (the group of the view, `ribbon.RightGroup`, captioned «Tabele», shown only while the page «Tabele» is on screen; `MainForm.UpdateViewGroup`). Switching on writes «switched ON» and the state of the page (`DbBrowserView.LogCurrentState`); switching off writes «switched OFF». The new control is a NEW KIND of `KBotRibbonField`, `KBotRibbonFieldKind.Check` (KBot.Controls: a `KBotCheckBox` made by the ribbon; properties `Caption`, `Checked`, event `CheckedChanged`; the field of the designer `fldNavLog`, key `tabele_log`). `KBotAdmin/TableNavLog.vb` writes `<AppDir>Logs	abele_navigare.log` (over 2 MB it moves to `tabele_navigare.old.log`; ASCII text, one line per event: time, [AREA], text). Areas: TABLES (list of tables, memory or server), TREE (click on the tree: new history or ignored), DBLCLICK (cell, value, JSON, the links found with source -> target columns, COMPOSITE flagged, or why none), LINK (link chosen, columns still to ask, step new or reused, why a jump stopped), ASK / VALUE / FETCH (the window for a composite key: text typed, narrowed locally or asked to the server and why, the call sent, count and hasMore, memory or server, value chosen, refused text), OPEN (request, key, parent, source MEMORY / SERVER, the db-table arguments, rows, step new or reused, a request not shown and why), MORE, RELOAD, CACHE (what a «Reincarca» cleared), BACK / FORWARD (what was clicked, the list offered, direct or popup, the one chosen), CLEAR, and HISTORY after every opened view: the current view, what back / forward offer, and the whole tree with the current view marked with «>».
